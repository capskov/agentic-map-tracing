# 从失败到修正：道路模块的现场经验

以下为去除工程标识的本地试验过程文字。原始影像、DWG、坐标、人工对象身份和实际叠加截图保留本地，未随包公开。读者目前不能用公开包独立重做这些现场案例；这些是经验记录，不是公开视觉基准。首页概念图不是案例的实际截图。

## 案例 A：树影露出的灰带，被误当作全部路宽

**观察与错误候选。** 支路被树影覆盖，露出的窄灰带被解释为主要路面，提出约5.5m候选，并已试画。

**矛盾如何出现。** 回到实际CAD窗口，并读取人工图层，发现两条长平行线表达约10m的断面示教。之前虽然保护了人工对象，没有改动它们，却没有实际使用它们表达的意思。

**怎样修正。** 撤下窄灰带候选，保留其被否决原因；核清人工示教的宽度与中心关系，再与主路分别重新顺接。人工线保持原样。

**学到什么。** 可见净空、树影间露出的铺装、完整路面是不同对象。保留人工图层不等于理解人工意图。人工示教也需区分示意与精描；这里保留的是核清后的断面关系。

**仍不能声称什么。** 约5.5m和约10m是此处影像/示教候选，不是测量宽度、规范值或其他道路的默认值。这个过程说明Agent能在核查后撤回错误，也说明它不是一次就判断正确。

## 案例 B：把真实渠化画成了“花瓶形”

**错误表现。** 边线分别追随局部亮暗和树影，并加上独立曲线控制点，导致道路无依据地鼓起再收回。即使改成两侧平行，若方向和共同位置来自薄弱取点，仍会偏。

**重新取证。** 从无叠线长段影像读取较清晰一侧的多处标线和另一侧无遮挡段，共同约束方向；分别辨认正常段、渐变起终点、稳定展宽段和口门。

**怎样修正。** 用共同道路带描述两侧及宽度变化，相邻段从同一组约束求接口；稳定段平行于共同标线方向，真实渐变单列，不继续分别调整两条S形线。

**学到什么。** 道路知识需要真正进入取点和几何约束。把“标线优先”写在文档中，不能证明执行时已经用上。平行关系要有正确的方向和定位支持，展宽也不必总是两侧对称。

**结果与边界。** 后续局部重判结果得到用户“比此前更好”的评价；树下外缘、路缘带与非机动车道的精确组成仍有不确定性。原生对象吻合和接点为零只证明执行与连接，不证明铺装精度。

## 案例 C：共用模板把错误传到四个转角

**错误表现。** 一个路口的南北来路不经分别核查，沿用同一竖直中心、宽度和圆角模板，四角因此共同失配；连接段曾把新终点硬塞回旧坐标，使新判断再次被拉偏。

**回修思路。** 重新看南北来路的长段走向与横断面，各角根据对应边界求切点和过渡；去掉旧坐标硬覆盖，让新老段通过一致几何关系衔接。

**学到什么。** 模板能保证形式一致，也会共同传播错误。系统复查要有独立清晰断面和逐角覆盖，不只统计检查了多少点。对称、相同半径、共同中心都需要影像支持。

**结果边界。** 该次回修有原生读回、接点和保存核验；树影下切点仍是推断，不能据此宣称四角已测量验收。后续样例不能沿用本例的宽度和半径。

## 工具问题也要进入记录

另一次观察发现，原生预览虽像素尺寸较大，但采用颜色很少的调色板；实际窗口截图保留更多颜色。它可能妨碍材质分界判断，因此增加原图与实际窗口复核。该显示问题并未被证明是所有几何偏移的原因，也不代表所有CAD预览都如此。

## 怎样补成公开可复现案例？

取得可公开影像或使用明确授权数据，保留原始像素与坐标约定，展示原图、失败候选、实际证据、修正候选及真实宿主叠加。将视觉贴合、几何执行和未确定事项分别评价，并记录所用Agent/工具配置。

当前包尚不包含这样的实景演示。下一步应补它，而不是把私人工程图或自制概念图包装成公开识别评测。
