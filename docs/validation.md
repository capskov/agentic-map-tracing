# 验证范围 / Validation scope

Agentic Map Tracing 当前只有道路专业 Skill。新增的项目定位、判图方法说明和去除工程标识的案例文字不增加已验证地物类型；规划中的建筑、步道独立模块、绿地和水系等尚未实现。

## 已测试环境与现场推荐

现场影像为18级卫星图；宿主与落图环境是Codex、AutoCAD及现有CAD智能底座。根据作者补充的使用反馈，GPT-6.1 Sol在Low推理投入下可用于完成常规描绘任务，建议以此作为使用起点，不推荐更低能力/推理投入配置；遮挡、渠化、复杂曲线或反复偏移等位置建议提高到XHigh，或由更强视觉推理Agent复判。

该推荐高度依赖Agent的视觉、空间推理和道路知识，并受提示、影像有效清晰度及复核执行影响。更清晰的真实源影像、更强Agent配合明确提示通常有助于复杂判断；单纯升高显示缩放级别或增加推理投入不保证消除错误。

模型与推理设置的正式配置没有形成完整的受控对照审计。“Low可完成”是作者的现场反馈，不表示已经证明其与高推理投入等效；“不建议更低”是使用建议，不是实测能力边界。18级也不等于统一地面分辨率或测量精度。

## 已有现场经验

方法来自同一实际工程的道路与管线穿路描绘：多处路口反复查看原始影像、CAD叠加及人工标记，局部修改后得到用户认可。后续暴露的问题包括中心共同选偏、标线语义未落实、路面与步道混淆、分别拉动边线造成不合理展宽、忽略人工长段示教，以及复查只检查了几何执行。

近期局部试验从无叠线长段重新解释标线，采用共同道路带约束，并保留了错误候选被否决的过程。现场还发现一类原生预览存在调色板量化问题，改用原图及实际窗口交叉复核。该观察不是所有CAD截图的普遍结论，也不证明所有偏移由截图引起。

Skill将这些教训抽象为可执行工作方法。所有工程图、影像、真实坐标和人工参考保留在本地，不随公开包提供。

## 已检查的内容

- Skill名称、frontmatter、入口及引用组织。
- 几何脚本的旋转仿射往返、半像素约定、法向宽度与逆向折点拒绝。
- 证据条带在现场影像的行、列两种模式；整理版还使用完全自制影像运行行列导出。
- 整理版的相对链接、公开文件清单，以及明显工程资料、缓存和本机路径排查。

脚本自检不等于道路识别评测，文件扫描也不等于证明任意未来添加的文件可公开。

## 未证明的内容

- 没有独立测量真值或跨地区、跨来源道路边线基准。
- 没有低推理投入与高推理投入的受控盲测；不能保证它们效果一致。
- 没有证明其他Agent或GIS宿主可以直接复用现有CAD适配。
- 没有全自动阻止所有漏检；道路语义和部分审阅步骤仍由Agent执行。
- 没有将影像推测自动转换为设计、测量或确定工程量的能力。

## 案例文字是否可独立复现？

纠错案例根据本地过程记录整理，公开包没有其原图或CAD截图，不能独立重做。案例说明假设如何被证据推翻，不是新实验或公开精度评测；尚需补充有权公开的完整实景演示。

## 概念图是什么？

`road-band.svg` 是自制的任意坐标几何示意，展示“等宽仍可整体偏移”“成对定位”“真实变宽单列”三种关系。它没有工程底图或真实坐标，不是识图结果，不能作准确率证据。

## 推荐的后续评测

在相同原始影像、人工示教和工具条件下，让不同模型/推理设置从干净上下文完成局部任务，不提供最终控制点。将训练过与未训练过的道路分开；同时评价两侧位置、走向、道路组成、宽度变化、口门连接、漏检与自我纠错。另列工具执行成功率，避免用保存成功替代视觉质量。
